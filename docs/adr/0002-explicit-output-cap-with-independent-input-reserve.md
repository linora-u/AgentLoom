# 输出上限必须有明确来源，输入预留单独管理

未配置输出上限时，框架不额外向 Provider 注入上限；显式正整数才形成调用方限制，配置覆盖中的 null 可解除继承。输入压缩预留与内部摘要预算单独管理，不能把 context window 当作模型最大输出能力。

必须提供上限的协议使用已核实的模型能力或要求显式配置；能力未知时提前报错。这个合同替代历史非 Codex 的隐式 16,384 默认值，已贯通配置、Pi/SDK 最终 HTTP payload 和 smol/LiteLLM 兼容入口。配置与回归覆盖见模型配置文档；真实 Provider 验证见输出预算实现验收记录。
