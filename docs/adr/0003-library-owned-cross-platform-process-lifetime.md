# 默认本机执行通过受管资源模块统一进程生命周期

2026-10-14，用户确认默认 macOS、Linux 均须支持 pip 安装后本机运行，使用本地持久状态并预留远程后端；不要求用户配置 launchd/systemd 或另行部署数据库、broker、服务，允许成熟第三方库自行启动和管理子进程。顶层执行 Python 被 SIGKILL 后，库自行启动的独立监护进程可以继续存活，但必须自动清理全部受管理任务后代并自行退出；本验收不同时强杀该监护进程。管理范围包含 Pi/Node、MCP、工具进程和孙进程，任务不得主动逃离，候选库必须有实际覆盖这一范围的依据，不能用重启后阻塞或手动清理代替自动回收。

这项部署与故障边界替代 ADR-0001 所记载的 macOS 专用执行方式。持久队列和恢复继续采用 DBOS 公开接口，AgentLoom 不新增调度器、领取循环或持久容量账本。

用户最新实施要求明确：只参考 OpenClaw 源码，禁止安装、执行、vendor 或打包其产品、SDK 和运行依赖。该要求撤销早期 SDK 接法；部署和强杀回收合同继续有效。默认资源模块沿用已有 Python、psutil 和资源注册入口，补齐可信启动闸门、独立 Python 监护及退出确认；不引入完整 Worker 平台或新的调度机制。普通调用者只配置并发数量，无 owner、插件或系统服务配置。

退出确认独立于业务完成和 DBOS 终态。监护以可信父连接的关闭触发清理，任务后代不能持有该连接；取消先关闭启动资格。物理清理或必要记录未确认时保留所有权及容量，通过公开状态和控制接口报告。有限 map 保留 live factory 和可信依赖，每次 map 有独立上限；持久化仍须显式调用，DBOS 负责跨 Run 的调度。

早期公开 SDK 原型在 macOS、用户指定的 `ssh dev` 上有局部成功证据，但原型已撤销，不能作为新 Python 实现的验收。当前合同及交付范围以[默认受管执行规格](../specs/default-managed-worker-execution-v3.md)为准；源码对应和实际测试记录见[资源所有权实现证据](../research/python-native-owner-20261014.md)。旧[接入规格](../specs/openclaw-process-owner-integration.md)仅保留为历史研究。
