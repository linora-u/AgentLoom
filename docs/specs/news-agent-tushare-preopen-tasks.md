## F1 对后续任务的公共合同

- 应用级 `news_window` 模块公开不可变的 `NewsWindow` 和 `resolve_window(as_of=..., trade_date=...)`。两种输入互斥；参考时间含时区，历史日期入口截止于当天 09:30，起点为前一交易日 15:00。使用 `exchange_calendars==4.13.2`、`XSHG`，检查覆盖边界。
- `NewsWindow` 至少公开 `trade_date`、`previous_trade_date`、`start`、`cutoff`，均保留正确类型，及 `to_dict()`/`from_dict()`。窗口元信息统一落在新准备 manifest 的 `news_window` 字段。
- 序列化字段至少有 `contract=preopen_window_v1`、`analysis_trade_date`、`entry_date`、`previous_trade_date`、`window_start`、`evidence_cutoff`、`mode`、`calendar`。`entry_date` 等于分析交易日。`calendar` 包含标识、库版本和覆盖范围。字段如需调整必须先通知协调者。
- 窗口公开完整时间记录与仅日期记录的纳入判断：完整时间起点包含、截止排除；日期型满足前一交易日日期不晚于记录日期，且早于分析交易日。
- 应用级 `news_sources` 模块提供单一默认来源策略及规范化/允许判断/稳定签名公共接口。来源别名、英文请求码与中文媒体名集中定义；允许从应用配置取得同一策略，供采集和准备共用。
- 应用级 `news_credentials` 模块公开 Token 解析：非空 `TUSHARE_TOKEN` 优先，否则读取本地 `token`。只注入环境变量时无需本地文件；缺失/错误不回显密钥。不要写回凭据。
- F1 负责日历依赖及其锁文件更新；F2 可增加必要的 PDF 解析依赖。后续代理在各自分支合并最新 integration 后再报告完成。

## F2

- 拥有新 `news_agent.tushare` 子包与采集相关测试，使用官方已验证的 HTTPS REST 根地址，不关闭代理或 TLS。
- 提供一轮采集公共入口，接受 `NewsWindow`、新闻根目录、来源策略及可替换外部请求边界，返回可序列化采集报告。
- 五类接口字段、来源码、时间切分及上限按 Spec；请求失败、饱和、解析失败、单条 PDF 失败均记录缺口并保留其他成功内容。
- 原始文件按原始发布日期保存，技术去重与同标题合并分离。兼容当前央行报告 manifest/文本/PDF 契约。
- 采集报告带完整性、缺口、有效行数、窗口和策略；成功空结果与全失败分开。
- 先实现并提交可运行的单条纵向测试，再扩展场景。不要修改 prepare/runtime/evaluation 或 CLI，以降低并行冲突。

## F3

- 拥有准备、Settings 中准备需要的字段、原始清理、runtime pipeline/store/query 的窗口传递及对应测试。
- 新 prepare 默认按目标交易日完整窗口；显式参考时间时使用传入截止。旧读取/评估产物可有清楚识别的兼容路径，但不能让新行为仅靠一个未接入默认入口的可选参数生效。
- 来源与时间筛选必须先于同标题合并；跨日 ID、PDF 和去重使用原始日期。
- 明确模板清理不能因为“广告”等普通业务前缀删去真实标题或正文。
- manifest/cache 绑定新窗口、来源策略、日历版本、日期精度和输入哈希；单条坏数据或文档形成缺口而不阻断其余分析。
- 初筛、精筛、校验统一本轮上下文，不再自动用目标日日末；保留原始时间供后修订检查。
- 不修改 evaluation、industry_net、公开 output/records 或 CLI；需要的接口变动写进代理报告供 F4/F5 接入。

## F4

- 拥有入场净判断、公开 output/records、evaluation baseline/period/replay、交易日推导及对应测试。
- 新合同从 manifest 取得显式分析交易日/入场日；旧合同保持只读可追溯，不将新目标日再移到下一交易日。
- 新窗口已经聚合同一入场的多个自然日新闻，避免二次跨目标交易日合并。
- 输出区分分析归属日和原始发布日期；不覆盖旧产物、不混淆旧语义。
- 周期/历史回放按开源交易日历逐目标交易日生成窗口。ETF 行情缺行不能被当成休市日。
- 保持净判断、持有期、阈值、候选池、评分合同；只修改窗口和归属。
- 不修改 prepare、pipeline/store、CLI。调用约定与 F1 窗口合同一致。
