# News Agent Tushare 采集与盘前分析设计

正式规格已整理到 [Tushare 新闻采集与 News Agent 盘前分析 Spec](news-agent-tushare-preopen-spec.md)。本文件保留前期设计讨论记录，后续实现与验收以正式规格为准。

状态：业务规则已梳理，待整体方案确认后实施。来源范围、同标题规则、指定参考时间取数、历史完整窗口、一轮采集后固定输入、失败部分跳过并继续分析，以及日期型内容整日纳入的规则已明确。本文件记录设计，不表示已经实现。

## 已确定的范围

| 新闻类别 | 来源范围 | Tushare 接口 |
| --- | --- | --- |
| 新闻快讯 | 财联社、华尔街见闻、第一财经、同花顺 | `news` |
| 长篇新闻 | 财联社、华尔街见闻、中证网、新华网、同花顺 | `major_news` |
| 新闻联播文字稿 | 全部 | `cctv_news` |
| 国家政策库 | 全部 | `npr` |
| 央行货币政策报告 | 全部 | `monetary_policy` |

来源范围同时约束新采集数据和历史文件产生的新分析输入。原始历史文件和既有运行结果保留。同一天、规范化标题相同的报道只保留一条，不比较正文，不区分类别和媒体。宣传稿、行情复述和无行业影响内容继续由已有初筛、精筛 Agent 判断。

## 代码位置建议

按用户指定，新增模块命名为 `applications/news_agent/tushare/`，负责 Tushare 请求、交易日与时间范围计算、分区写入、采集结果记录及央行 PDF 下载和文本提取。采集命令接入现有 `news-agent` CLI。接口依赖与新增包声明放在新闻应用自己的 `pyproject.toml`。

在应用配置中保存一份来源范围，采集和 `processing/prepare.py` 共用。快讯请求使用英文来源码，长篇请求使用中文来源名，由同一份配置负责对应关系。

凭据支持 `TUSHARE_TOKEN` 环境变量及应用配置目录中的 `tushare.local.yaml`（字段 `token`）。非空环境变量优先，本地文件兜底；本地文件需被 Git 忽略并排除在应用分发包之外，仓库提供空模板。实际读取支持随采集功能实现。

交易日历使用开源库 `exchange_calendars` 的 `XSHG` 日历，由应用内共用的日历与窗口模块提供给采集、准备和评估，不调用 Tushare `trade_cal`，也不依赖 Token。运行记录保留日历版本及覆盖范围，超出范围时明确提示更新。

`prepare` 在同标题合并前执行来源过滤，避免未选来源先占据保留记录。来源范围需要进入准备结果的清单和缓存判定；范围变化后的分析使用新的运行目录，避免复用旧来源的已准备输入。

## 已确定的运行方式与改造范围

- 实际日常运行在早上开盘前，每天分析一次；同时支持按指定历史交易日获取和分析新闻。不设计持续更新或同一天盘中反复分析的业务流程。
- 不使用“实时”描述参数取数：调用者可以显式传入参考时间，不能在程序执行期间不断移动截止时刻。
- 统一以目标交易日的盘前窗口组织新闻：前一个交易日收盘至目标交易日开盘。A 股场景采用北京时间 15:00 收盘、09:30 开盘，节假日按交易日历回溯。例如周一完整盘前窗口为上周五 15:00 至周一 09:30。
- 日常指定参考时间的取数截止与历史完整窗口的开盘截止分别明确，不把盘前尚未发生的时间段称为已经取得的新闻。
- 分析范围可以跨自然日，不再默认只取昨天；新闻输入是一批有限内容，不建立实时新闻处理流。
- 盘前启动后完成一轮 Tushare 采集，再固定实际输入并分析；此后新到的新闻不再追补本轮。不另建多时点采集调度或持续采集进程。
- 一轮采集可以包含多个来源请求和为避开条数上限而细分的时间段，不表示只发一个 API 请求。
- 同标题处理仍按每条新闻所属自然日和规范化标题判断，不因一个分析窗口跨日而把不同日期的同标题记录合并。
- 仅有日期的记录按整日纳入，并标记“仅日期”：包含从窗口起始交易日到目标交易日前一个自然日的全部日期，不做 15:00 切分，不纳入目标交易日当天仅有日期的记录。周末、节假日处于该范围内的内容一并包含。例如周一分析时，纳入周五、周六、周日全天的日期型内容。
- 指定来源、时间段或单条文档采集失败时，跳过失败部分，保留成功取得的内容并继续分析，不等待补齐。应记录并告知用户采集缺口。
- 飞书机器人通知属于用户提出的后续集成方向；首版先输出明确错误提示和缺口报告，当前不接入机器人、不发送消息。
- 新增采集模块不是全部范围：原有新闻准备、初筛、精筛、校验及历史评估必须共同使用新窗口，只分析既定来源范围内的输入。

## 输入入口建议

两种入口共用窗口计算、采集和分析流程，不分别实现两套业务逻辑：

| 入口 | 输入 | 新闻范围 |
| --- | --- | --- |
| 指定参考时间 | `as_of`，显式传入带时区的时间 | 前一交易日 15:00 至指定参考时间；盘前参考时间不延伸到尚未发生的 09:30 |
| 指定历史交易日 | `trade_date` | 前一交易日 15:00 至该交易日 09:30，开盘时刻起的新闻不纳入 |

历史交易日入口可以转换成该交易日开盘时刻的截止参数，再进入同一条处理链路。具体 CLI 参数命名在实现时保持与现有命令风格一致。

分析交易日与新闻原始日期分别存储：例如周一的分析包含周五、周末及周一盘前新闻，判断归属周一，但各条新闻仍保留其实际原始日期。

## 配套改造要求

- 每次分析固定一个截止时刻，组装完成后保存该次实际使用的输入，后续采集不能改变正在运行的分析。
- 准备流程支持起止时间，按涉及的自然日读取原始分区，再按发布时间筛选；按天组织原始文件不妨碍跨日分析。
- 运行记录、证据截止及缓存身份记录分析起止时间和输入版本，不能继续只依赖新闻日期或当天 `23:59:59`。
- 只有日期、没有可靠时分秒的记录保留真实时间精度，不能伪造精确发布时间。

## 原有分析与评估的配套整改

| 环节 | 当前约束与改造要求 |
| --- | --- |
| 原始准备 | 当前只扫描一个自然日。改为扫描窗口覆盖的日期分区，先做来源及时间范围筛选，再沿用同原始日期、同标题去重。 |
| 新闻 ID 与央行文档 | 当前用传入的新闻日生成 ID、查找 PDF。跨日后仍用原始分区日，不能全部替换为分析交易日。 |
| 准备清单与缓存 | 记录分析交易日、窗口起止、实际截止、来源范围、日期精度规则及输入版本，避免复用不同口径的旧缓存。 |
| 初筛、精筛、校验 | 共用同一个已固定的结构化窗口；修改“某个自然日”及日末截止的旧上下文和提示，不让各阶段自行推导窗口。 |
| 校验证据 | 证据截止跟随本次输入截止，不能继续写目标交易日的 23:59:59；保留原始新闻日期，避免破坏正文后来修订的检查。 |
| 入场净判断与公开输出 | 围绕目标交易日形成一次入场判断，适配旧的跨自然日聚合；输出区分判断归属日期与新闻发布时间。 |
| 单日评估、周期评估、历史回放 | 显式使用目标交易日作为入场日，不再对它执行“找下一交易日”；历史批量按目标交易日生成对应窗口。 |

现有队列与三阶段执行机制可以复用。新窗口和来源范围产生新运行，不覆盖已经提交或完成的旧输入与旧评估。

## 失败时的行为

- 请求可进行有限次数重试；仍失败就结束该部分请求，继续其余采集和分析，不无限等待。
- 缺口记录包含新闻类别、来源、时间范围或文档、失败原因，以及本轮成功取得的数量。合法空响应和请求失败分别记录。
- 运行记录及分析结果明确标记本轮采集是否完整；部分失败不被标成“完整采集成功”，也不因为个别采集失败让整个分析流程提前退出。
- 文档下载或正文提取失败只跳过受影响的文档，不使其他成功内容失效。
- 如果最终没有可分析内容，则输出本轮无可分析输入及相关缺口，不让 Agent 生成没有输入依据的行业判断。全部请求失败与成功取数但无新闻应分别说明。
- 后续飞书机器人使用相同缺口信息通知用户；首版不要求机器人凭据。

## 已核实的约束

- 当前仓库只读取已导入的新闻 Parquet，没有五类新闻的 Tushare 采集实现。历史文件来自另一数据处理项目。
- 当前 `day: latest` 指本地下载清单的截止日期；工作 Agent 的上下文按新闻日 `23:59:59+08:00` 截止。盘中采集截止与完整自然日不是同一概念。
- 当前新闻日被转换为下一交易日入场；若仅将该日期改成目标交易日而不调整入场计算，单日和周期评估会错误地再推后一个交易日。
- `news` 每次最多 1,500 条，`major_news` 最多 400 条，`npr` 最多 500 条。官方文档没有列出分页游标；达到上限需要细分时间窗口，仍饱和时明确记录未完成。
- 长篇正文、国家政策正文及原始链接需要显式请求。新闻联播按自然日请求，央行报告按日期区间请求。`cctv_news.date` 和 `monetary_policy.pub_date` 只有日期，没有可靠时分秒；现有本地原始记录也只有日期，不能简单补成午夜后进行精确时段筛选。
- 现有央行报告准备流程要求 PDF、提取文本及带哈希的文档清单。仅保存接口的 HTML 字段无法直接满足现有读取契约。
- 官方没有给出新闻逐源延迟或完整性保证。采集需要区分发布时间与实际获取时间；用户已选择本轮固定输入后不追补迟到数据。
- 官方 REST 文档与 SDK 源码仍展示 HTTP 地址；实际部署所用传输需要核验。本轮没有读取凭据或调用带 Token 的接口。

## 日期精度规则

有完整发布时间的记录按精确窗口筛选；仅有日期的记录按以下范围整日纳入，两种入口采用同一规则：

```text
前一交易日的日期 <= 记录日期 < 目标交易日的日期
```

例如普通周二包含周一全天的日期型内容；周一包含上周五、周六、周日全天；节假日按前一交易日到目标交易日前一天的范围包含。不能仅取周日而漏掉周五和周六，也不能把日期补成午夜后错误排除起始交易日。

目标交易日当天仅有日期的记录不纳入，避免历史回放将晚间联播或盘后央行报告提前用于当天开盘。起始交易日 15:00 前的日期型记录可以进入，这是用户选择的按整日收取规则；不将这些记录宣称为精确满足秒级窗口。

本轮采集输入只证明该版本在实际获取时已经可用。历史回放不能据此推定内容在过去某个盘前时刻已经可用；本次改造不自动为旧历史数据补造可用时间。

已确定的来源、同标题规则、指定参考时间、一轮采集及失败处理不再重新提问。盘后实时分析、同一天多次分析和多时点定时采集不属于首版范围；历史窗口获取和历史分析属于本次范围。

## 实施验证重点

- 指定盘前时刻与历史开盘截止的窗口计算一致，覆盖普通交易日、周末及节假日。
- 来源过滤先于合并；同一天同标题只保留第一条，不同原始日期的同标题分别保留。
- 日期型记录包含起始日全天和窗口内休市日，排除目标日当天；完整时间记录按真实起止时间筛选。
- 跨日央行报告仍按原始日期查找 PDF 和提取文本；单条文档失败不影响其他输入。
- 部分来源失败时分析继续，产物携带缺口；合法空结果与请求失败分别说明。
- 分析、校验证据截止、输出归属及单日/周期评估使用同一个窗口和目标交易日，避免晚间事实提前进入或入场日期错后一天。
- 新窗口或来源范围不能命中旧口径缓存，不覆盖旧运行。
