The framework adapter imports upstream `Proposer`, `run_task` and `Library`; the distribution installs the actual `harness2` package. Replaced local recursion/selection branches, the separate Library, five shortened method prompts and whole-tree edits JSON are removed. There is one method controller. See [provenance](../../third_party/harness2/PROVENANCE.md), [finite patches](../../third_party/harness2/harness2/PATCHES.md), [the adapter](../../src/app/harnessing/upstream.py) and [configuration/runtime guidance](../cn/harnessing.md).

```text
complete Application Task
  -> pinned upstream recursion / Probe / Compose / final selection
       -> Pi reads and edits isolated candidate files
       -> trusted complete Application execution and acceptance
  -> publish the selected existing result
  -> upstream reflection / Library for the next declared task
```

All five available improvement roles use Pi. Finite positive `k` controls the normal plan of `4k` complete business Trials and `3k` proposal/composition sessions; selection, reflection, evaluation, actual requests and retries are counted separately. Only accepted, cleaned composed finals enter selection. `k=1` adopts its sole eligible final without a ranking call; no eligible final means explicit failure. A successful baseline or Probe is not a fallback final. Unchanged candidates and `NO_ENTRY` are valid outcomes, not forced edits or invented lessons.

Adoption publishes an already executed result. It does not rewrite source YAML, create a Git commit or replace the next task's declared base. The upstream comparison at the pinned revision records 101 byte-identical files, six documented patched files, seven omitted promotional media assets and no missing source files. Installed execution has no temporary upstream-checkout dependency.
