# Tushare 新闻采集与 News Agent 盘前分析 Spec

日期：2026-10-16

状态：规格已整理；业务实现和功能验证尚未开始。

本规格汇总本次讨论的业务要求，覆盖新采集能力及原有分析、校验、评估链路的配套整改。

## Problem Statement

用户需要直接从 Tushare 获取指定来源的新闻，用于 A 股及行业 ETF 的盘前判断，也需要重建指定历史交易日的盘前新闻输入。

目前 News Agent 主要消费从其他项目迁移的历史新闻文件，没有这五类新闻的直接采集能力。原有流程以新闻自然日为单位准备输入，分析上下文的证据截止固定为日末，再把新闻日映射到下一个交易日入场。这个口径无法表达“前一交易日收盘到目标交易日开盘”的跨日窗口，也不能准确表达调用者传入的盘前截止时间。

只新增下载程序会留下三个问题：旧准备流程仍可能读入未选来源和窗口之外的新闻；校验仍可能使用开盘后的事实；如果直接把旧新闻日替换为目标交易日，评估会再推后一个交易日。用户需要的是从采集到评估一致的盘前分析能力。

用户还要求每天仅处理一批固定输入，不持续追补新到新闻；某个来源或文档失败时，跳过失败部分并通知，其他内容继续分析。

## Solution

在 News Agent 应用内增加 `news_agent.tushare`，接入现有公开 CLI。调用者可以指定参考时间，或指定一个历史分析交易日；两种入口共用窗口计算、采集、准备和三阶段分析流程。

来源范围固定为：

| 新闻类别 | 允许来源 | Tushare 接口 |
| --- | --- | --- |
| 新闻快讯 | 财联社、华尔街见闻、第一财经、同花顺 | `news` |
| 长篇新闻 | 财联社、华尔街见闻、中证网、新华网、同花顺 | `major_news` |
| 新闻联播文字稿 | 全部 | `cctv_news` |
| 国家政策库 | 全部 | `npr` |
| 央行货币政策报告 | 全部 | `monetary_policy` |

“全部”表示不额外限制该接口提供的来源或机构，不表示 Tushare 覆盖现实世界的全部新闻、政策或报告。

两种取数入口的业务语义为：

| 入口 | 输入 | 有完整发布时间的新闻范围 |
| --- | --- | --- |
| 指定参考时间 | 调用者显式传入参考时间 | 前一交易日 15:00 至该参考时间 |
| 指定历史交易日 | 指定分析交易日 | 前一交易日 15:00 至该交易日 09:30 |

交易日历采用公开开源库 `exchange_calendars` 的 `XSHG`（上交所）日历，本地计算交易日及开收盘时刻，不依赖 Tushare 的交易日历接口或 Token。窗口计算、历史回放与评估共用此日历。

统一使用北京时间。仅有日期的记录按整日收取：从前一交易日的日期起，到分析交易日前一个自然日为止，包含其间周末和节假日；不纳入分析交易日当天仅有日期的记录。例如周一分析时，这类记录包含周五、周六、周日全天。

一轮采集结束后固定本次实际输入，再交给初筛、精筛和校验。来源和时间范围过滤先于同标题合并；合并继续采用用户确定的“同原始日期、同规范化标题保留第一条”规则。宣传稿、行情复述和无行业影响内容由现有 Agent 做语义判断。

结果归属分析交易日，策略从该交易日开盘入场。部分采集失败不会阻断其余内容分析，采集缺口随结果披露；飞书机器人通知作为后续集成，本规格先提供可供通知使用的缺口信息。

## User Stories

1. 作为 News Agent 使用者，我希望直接从 Tushare 获取新闻，以便不再依赖从其他项目手动搬运数据。
2. 作为盘前研究者，我希望快讯只使用财联社、华尔街见闻、第一财经和同花顺，以便将注意力集中在已选来源。
3. 作为盘前研究者，我希望长篇新闻只使用财联社、华尔街见闻、中证网、新华网和同花顺，以便获得既定范围内的深度内容。
4. 作为盘前研究者，我希望保留接口范围内的全部新闻联播文字稿，以便不漏掉其中的政策及行业信息。
5. 作为盘前研究者，我希望国家政策库不额外限制发布机构和政策类别，以便覆盖接口提供的政策信息。
6. 作为盘前研究者，我希望取得接口范围内的全部央行货币政策报告，以便分析货币政策对行业的影响。
7. 作为程序调用者，我希望显式传入参考时间，以便准确控制本轮新闻截止，而不依赖执行过程中的系统时间变化。
8. 作为历史研究者，我希望指定历史交易日获取完整盘前新闻，以便重建前一交易日收盘到该日开盘的输入。
9. 作为历史研究者，我希望也能传入过去的盘前参考时间，以便分析当时更早截止的一批新闻。
10. 作为盘前研究者，我希望通过公开开源库在本地取得交易日历，以便无需 Tushare 日历权限也能正确处理周末和节假日。
11. 作为盘前研究者，我希望有完整发布时间的新闻按精确时间筛选，以便排除前一交易日收盘前及本轮截止后的内容。
12. 作为盘前研究者，我希望仅有日期的内容按整日纳入，以便不因补成午夜而错误排除前一交易日的有效内容。
13. 作为历史研究者，我希望仅有日期的记录截止到目标交易日前一天，以便不把目标交易日晚间新闻提前用于开盘判断。
14. 作为结果使用者，我希望新闻保留真实发布时间及其精度，以便区分精确时刻与仅日期信息。
15. 作为日常使用者，我希望每天盘前采集一轮后固定输入并分析一次，以便获得边界明确的结果。
16. 作为日常使用者，我希望本轮分析不追补随后新到的新闻，以便输入和结果不会在运行途中发生变化。
17. 作为历史数据使用者，我希望旧文件产生的新分析也遵守来源范围，以便历史结果与新采集结果采用同一口径。
18. 作为盘前研究者，我希望同一天同标题的新闻只保留第一条，以便减少重复输入。
19. 作为盘前研究者，我希望同标题合并不比较正文、不区分类别和媒体，以便保持已经确定的去重规则。
20. 作为盘前研究者，我希望不同原始日期的同标题新闻分别保留，以便跨日窗口不会误合并不同日期的记录。
21. 作为盘前研究者，我希望无标题的不同快讯分别保留，以便空标题不会成为误合并的依据。
22. 作为结果核查者，我希望合并后的记录仍可追溯原始记录及来源，以便核查保留记录的出处。
23. 作为盘前研究者，我希望长篇和政策正文被实际请求并保存，以便 Agent 分析正文而不只分析标题。
24. 作为盘前研究者，我希望央行报告使用可核查的 PDF 正文，以便延续项目现有的报告读取和版本溯源要求。
25. 作为日常使用者，我希望某个来源或时间段拉取失败时跳过该部分，以便其余有效新闻仍能进入分析。
26. 作为日常使用者，我希望看到失败来源、时间段和原因，以便了解本轮数据缺口。
27. 作为结果使用者，我希望区分合法空结果与采集失败，以便不会把接口错误理解为没有新闻。
28. 作为结果使用者，我希望没有任何可分析输入时得到明确说明，以便不会收到没有新闻依据的行业判断。
29. 作为盘前研究者，我希望已有初筛和精筛判断宣传、行情复述及行业影响，以便混合有效事实的文章不会被简单关键词整篇删除。
30. 作为盘前研究者，我希望初筛、精筛和校验共用同一新闻窗口，以便各阶段不会对时间边界作不同解释。
31. 作为历史研究者，我希望校验证据遵守同一个截止时刻，以便开盘后事实不会进入盘前判断。
32. 作为结果使用者，我希望判断归属目标交易日、新闻保留原始日期，以便不会混淆分析日期与报道日期。
33. 作为策略评估者，我希望从目标交易日开盘评估入场，以便不会因为旧的日期映射多推迟一天。
34. 作为策略评估者，我希望单日、周期和批量历史分析使用一致窗口，以便不会重复归属同一次入场或漏掉休市期间新闻。
35. 作为结果核查者，我希望新输入具有固定版本并与旧运行隔离，以便可以复查结果且保留既有历史产物。
36. 作为运行维护者，我希望通过环境变量或本地专用配置文件提供凭据，以便兼顾云端配置和本地使用，且不把真实密钥写入仓库或结果文件。
37. 作为运行维护者，我希望采集处理接口条数上限并记录仍未取完整的部分，以便不会把截断响应误认为完整数据。
38. 作为运行维护者，我希望缺口信息可以供后续飞书机器人使用，以便增加通知时不必重新定义采集失败信息。
39. 作为实现者，我希望通过现有公开 CLI 和受控 Worker 验证完整流程，以便测试能发现跨模块的日期与截止不一致。
40. 作为历史研究者，我希望明确历史下载的版本与可获取时间限制，以便不会把事后获取的数据当成当时可用数据的完整证明。
41. 作为云端任务发起者，我希望仅通过环境变量注入 `TUSHARE_TOKEN` 即可使用采集功能，以便在没有本地私密配置文件的环境中运行。

## Implementation Decisions

### 1. 模块与职责

- 在新闻应用内新增 `news_agent.tushare`，承担 Tushare 新闻请求、原始数据保存、采集缺口记录和央行报告文档获取。不创建独立应用或另一套执行引擎。
- 通过应用内共用的交易日历与窗口计算模块适配开源库 `exchange_calendars`，供采集、准备、分析和评估调用；日历查询不要求 Tushare 凭据，也不调用 `trade_cal`。
- 采集能力接入现有公开 CLI，并能衔接既有准备和三阶段分析。两种输入入口使用同一处理链路，不能分别实现两套来源或时间规则。
- 来源范围由应用配置统一定义，采集与历史准备共同使用；不将项目偏好写入官方 Tushare skill。
- 修改现有准备、三阶段上下文、证据时间校验、入场净判断、公开结果、单日评估、周期评估及历史回放的相关接口，使其传递同一个窗口合同。
- 复用现有持久执行、阶段队列、Worker 和业务完成回执机制，遵循既有本地持久执行 ADR。本功能不修改执行引擎和进程所有权模型。
- 新增依赖和应用子包声明归属于新闻应用，不依赖未声明的开发机环境。

### 2. 输入与窗口合同

- 对外支持两个互斥输入：指定参考时间 `as_of`，或指定历史分析交易日 `trade_date`。具体命令组织沿用现有 CLI 风格，不能要求调用者另外计算前一交易日。
- 参考时间带明确时区并统一转换为 `Asia/Shanghai`。调用参数在入口解析后固定，不随采集或模型执行时间滚动。
- 本规格的参考时间入口服务于交易日盘前及开盘边界；不自动解释盘中、盘后或休市日参考时间。日期与时间参数不合法时，返回明确参数错误。
- 交易日入口的分析交易日必须是有效交易日。使用 `exchange_calendars` 的 `XSHG` 日历查找严格早于它的前一交易日，以库返回的交易日、开盘和收盘时刻计算窗口，再转换为北京时间。不以工作日规则、法定调休工作日或 ETF 行情是否缺行推断交易日。
- 使用经验证的库版本并锁定依赖，在运行清单中记录日历标识、库版本及适用日期范围。超出库支持范围时提示更新日历数据或版本，不静默推算节假日，也不回退到 Tushare 日历接口。
- 窗口起点为前一交易日 15:00。参考时间入口的截止为传入时间；历史完整窗口的截止为目标交易日 09:30。包含起点，排除截止时刻及之后的完整时间记录。
- 历史交易日入口可以先转换为开盘截止，再进入共用流程。既支持完整历史窗口，也允许以过去的盘前参考时间建立更早截止的历史输入。
- 区分分析交易日、原始新闻日期、窗口起点、新闻截止时刻、实际获取时间和输入固定时间，不能继续让单个 `day` 同时承担这些含义。
- 无法确定可信交易日边界时，报告日历或输入错误，不猜测窗口。这与已确定窗口内某个新闻来源失败的跳过策略分别处理。

### 3. 来源映射与接口字段

| 新闻类别 | 请求来源或范围 | 必须取得的内容 |
| --- | --- | --- |
| 新闻快讯 | 财联社 `cls`、华尔街见闻 `wallstreetcn`、第一财经 `yicai`、同花顺 `10jqka` | 新闻时间、标题、正文；保留可返回的频道信息 |
| 长篇新闻 | 使用允许来源的中文名称 | 显式请求 `title`、`content`、`pub_time`、`src`，不能依赖默认字段包含正文 |
| 新闻联播文字稿 | 按日期请求，不加来源过滤 | 日期、标题、正文 |
| 国家政策库 | 不额外限制发布机构、政策类别 | 显式请求 `pubtime`、`title`、`url`、`content_html`、`pcode`、`puborg`、`ptype` |
| 央行货币政策报告 | 不加来源过滤，按日期范围请求 | `pub_date`、`title`、`url`、`pdf_url`、`content_html`，并获取可用的 PDF 正文 |

- 请求来源与文章引用的原始出处分别保留。来源过滤使用类别内提供内容的来源，不用转载正文中的署名覆盖它。
- 来源校验同时作用于新请求、响应规范化及旧文件准备；未选来源不能因历史缓存或别名处理绕过限制。
- “全部”类别仍受本次日期或时间范围约束。

### 4. 有限采集与请求完整性

- 一轮采集可包含多个来源请求和必要的分窗请求；不将“一轮”实现成每个接口只允许请求一次。
- `news`、`major_news`、`npr` 的已知单次上限分别为 1,500、400、500 条；央行报告接口已知上限为 1,000 条。上限在适配层集中管理。
- 达到上限时按接口支持的时间精度继续细分范围；不使用官方未提供的分页游标假装完成遍历。
- 最小时间范围仍饱和、请求失败或响应不可解析时，记录受影响范围及已取得内容，不将其标成完整采集。其他成功内容继续进入处理。
- 网络请求使用有限超时和重试，不无限等待。相邻请求的重叠记录先按原始记录身份消重，不能混淆技术幂等与业务同标题合并。
- 采集完成仅表示本轮计划请求没有已知获取缺口，不承诺数据商不存在延迟补录、漏收或之后修订。

### 5. 时间精度与原始数据

- 有完整发布时间的记录按真实起止时间筛选，保留原始时间字段和统一时区后的时间。接口边界是否包含结束时刻，不改变本地最终筛选规则。
- 仅有日期的记录采用整日规则：记录日期不早于前一交易日，且早于分析交易日。两种入口采用相同规则。
- 起始交易日全天的日期型内容都可纳入，包括 15:00 前；窗口内周末和节假日也全部包含。目标交易日当天的日期型记录不纳入，不通过补成午夜绕过限制。
- 日期型记录保留“仅日期”标记，不伪造精确发布时刻。无法解析日期或时间的记录不能随意归到分析交易日；应跳过并记录原因。
- 原始数据按实际原始日期组织并保留原始字段、来源及记录身份。分析交易日不改变原始分区日和文档归属日。
- 实际获取时间描述本项目取得该版本的时间，不冒充新闻首发时间或过去的首次可获取时间。

### 6. 央行报告正文与兼容契约

- 采集同时负责报告 PDF 获取和文本提取，使用成熟文档解析能力。仅保存接口 HTML 不能视为已满足现有报告准备契约。
- 原始行与文档清单通过稳定原始哈希关联；保留接口声明的 PDF 地址、实际下载地址、PDF 文件和提取文本的校验哈希、页数及版本依据。
- 延续现有报告读取需要的原始哈希、声明地址、PDF 与文本位置、文本哈希等字段含义，使跨日准备仍能验证对应关系。
- 获取、哈希核验或正文提取失败只影响该文档，并形成采集缺口；不能因此丢弃其他成功新闻。
- 保存正文版本依据，不把后来重新导出或修订的 PDF 自动认定为首次发布版本。

### 7. 准备、同标题合并与内容判断

- 准备流程扫描窗口覆盖的全部自然日分区，先执行来源范围和时间精度筛选，再做同标题合并与现有分段。
- 同标题规则保持为“原始新闻日期相同且规范化标题相同”。标题规范化沿用 NFKC、大小写折叠和空白归一；不加入来源、类别或正文作为合并条件。
- 保留既有稳定读取顺序中的第一条正文，其他记录可保留 ID 和来源溯源；不引入最长正文、正文相似度或媒体优先级选择。
- 不同原始日期的同标题分别保留。没有可用标题的不同记录不合并。
- 记录 ID、原始日期、央行文档定位仍依赖原始新闻身份，不统一改成分析交易日。
- 程序承担来源、时间范围、格式与明确模板清理，不新增基于“广告”“获奖”“涨停”等词的整稿淘汰器。
- 初筛继续识别纯宣传、行情复述和无行业影响内容；精筛继续判断新增事实及行业传导。混合有效事实或存在不确定性的内容应交由既有 Agent 语义判断。

### 8. 三阶段分析、证据与入场归属

- 准备完成时固定窗口及输入版本，初筛、精筛、校验从同一份结构化信息取得分析交易日、新闻截止和来源范围，不在各阶段重新推导。
- 更新仍描述单个自然日或固定日末截止的上下文、提示和相关引用，明确输入可能包含多个自然日。
- 证据截止跟随本轮新闻截止，不能继续使用分析交易日 23:59:59。证据的发布时间及版本可用时间继续接受既有时间完整性校验。
- 保留原始新闻时间，以维持对后来修订正文的检查。日期型新闻的整日纳入不代表可以放宽外部校验证据的版本约束。
- 输入来源白名单约束待分析新闻；现有独立证据校验机制继续使用，不将外部证据自动加入本轮待分析新闻池。
- 一次完整盘前窗口已经服务于一个分析交易日。旧的跨自然日入场净判断需要按该归属适配，避免把多个分析交易日再次合并为一次入场。
- 公开结果明确区分判断归属日与原始新闻发布时间及其精度；通过版本化或兼容字段表达，不能无说明地给旧产物改含义。
- 入场日显式等于分析交易日。单日评估、周期评估和历史回放不得再对它执行“找下一交易日”。
- 延续现有净判断、持有期、阈值与计分规则，仅修正输入范围和时间归属；历史批量按交易日生成各自窗口，不能继续要求为周末分别生成入场产物。

### 9. 采集缺口与运行结果

- 指定来源、时间范围或单条文档失败时，有限重试后跳过受影响部分，继续采集和分析其余有效内容。
- 缺口报告至少包含类别、请求来源、受影响时间范围或文档、失败原因、尝试情况和成功取得数量；不记录凭据值。
- 合法空响应、失败响应及达到上限仍未取完整分别记录。不能将失败转换为“该来源没有新闻”。
- 采集完整性与分析阶段完成状态分别表达。成功内容可以完成三阶段分析并封存，同时仍披露本轮采集缺口。
- 部分获取失败不使整个分析编排提前退出，也不能让现有通用错误处理先抛出而绕过缺口报告。已有分析 Worker 的提交和失败合同保持独立。
- 最终没有可分析输入时，输出明确的无输入结果及采集状态，不调用 Agent 编造行业判断。全部请求失败与全部请求成功但无新闻分别说明。
- 首版在命令结果及运行产物中提供缺口信息。飞书机器人后续接入，本次不要求 webhook、用户标识或机器人凭据。

### 10. 固定输入、缓存与历史兼容

- 一轮采集和准备完成后，记录实际输入及其哈希，分析过程中不随原始数据新增而改变。
- 准备缓存身份至少覆盖窗口起止、分析交易日、日历标识及版本、来源策略、日期精度规则、输入版本，以及原有分段和内容签名参数。
- 新来源范围和新窗口不能命中旧口径缓存。新准备输入使用新运行身份，不原地替换已提交输入或覆盖旧结果。
- 已有原始历史数据可以按新来源和窗口重新准备；旧运行保持原口径可追溯，不能仅改输出日期伪装成新口径结果。
- 技术层面的幂等保存和已有运行恢复可以复用；不新增“同一天多次盘中分析”的业务流程。

### 11. 凭据与实际接口验证

- 同时支持现有 `TUSHARE_TOKEN` 环境变量与本地专用 Tushare 配置。优先读取非空环境变量；未设置时读取本地配置中的 `token`；两者均无有效值时明确报告凭据缺失，不使用内置默认 Token。
- 后续实现必须支持由终端、任务启动器或云端运行环境通过标准环境变量注入 `TUSHARE_TOKEN`。环境变量有有效值时，不要求本地凭据文件存在；变量需要传递到实际发起采集请求的执行单元，不能仅在命令入口可见，也不能将注入值自动写回配置文件。
- 本地专用配置与现有应用配置放在同一配置目录，但必须同时被 Git 忽略并从应用分发包排除。仓库只提供 Token 为空的模板，不把真实 Token 写入代码、配置模板、原始记录、日志或规格。
- 各类接口权限分别验证，不假定快讯权限同时覆盖政策库和央行报告。权限不足按相应来源缺口报告并继续其余内容。
- 请求传输及部署环境的代理兼容性在实现阶段实际核验，不根据文档网站使用 HTTPS 就推断普通 REST 或 SDK 具有相同能力。本规格不虚构已完成的云端连通验证。

## Testing Decisions

### 主要验收边界

优先通过公开 CLI 与现有 `NewsService` 工作流验证，从给定时间参数和来源响应出发，观察实际准备输入、三阶段上下文、运行结果、缺口报告及入场评估。使用真实本地持久化和数据文件，复用现有受控 Worker 测试设施；外部模型和搜索不作为普通回归测试的必要依赖。

新增测试替身集中在采集的外部请求边界，为 Tushare 新闻接口和文档获取提供可控响应。交易日历使用已锁定的真实开源库，选择其覆盖范围内的已知日期，不模拟网络日历接口。业务模块之间保持真实调用，不为窗口、去重、缓存、准备和评估各造一套替身。仅在端到端失败难以定位时，补充窗口与时间完整性等现有低层接口的边界测试。

好测试应验证调用者能观察到的行为：哪些记录进入分析、截止是否一致、是否继续处理成功内容、缺口是否披露、入场是否在目标日。不要断言私有函数调用顺序、内部拆窗次数或复制实现算法来计算预期值。

### 验收场景

| 编号 | 场景 | 可观察的验收条件 |
| --- | --- | --- |
| T1 | 普通交易日指定盘前参考时间 | 从前一交易日 15:00 取到指定截止；起点前和截止起的完整时间记录不进入分析，三阶段证据截止一致。 |
| T2 | 指定历史交易日 | 窗口截止为该日 09:30，结果归属该日，评估从该日开盘入场，不推到下一交易日。 |
| T3 | 开源日历、周一、节假日及跨年窗口 | 无 Token 时也能单独计算窗口；前一交易日由真实 `XSHG` 日历确定，覆盖跨年、长假和调休周末；超出库覆盖范围时明确报错，不请求 Tushare 日历或按星期推测。 |
| T4 | 日期型内容 | 起始交易日全天和中间休市日全部纳入；目标日当天排除；记录保留仅日期精度，不伪造时间。 |
| T5 | 来源过滤与同标题交叉 | 未选来源先出现也不能占据保留正文；同原始日跨媒体或类别同标题仅保留第一条，不同原始日分别保留，空标题分别保留。 |
| T6 | 非默认正文及来源映射 | 快讯使用正确来源码；长篇和政策结果具有正文、政策原始链接，不因遗漏请求字段而只有标题。 |
| T7 | 跨日央行文档 | 使用原始日期和原始哈希找到对应 PDF、文本及元信息；损坏或缺失文档只跳过受影响记录。 |
| T8 | 条数上限与边界重叠 | 饱和范围继续获取；最终拿到完整测试集合或明确留下缺口，不静默截断，也不因请求重叠制造重复输入。 |
| T9 | 部分来源超时、拒绝或权限不足 | 成功记录仍完成分析；缺口报告包含失败范围和原因；采集完整性不被误报为完整。 |
| T10 | 无输入的不同原因 | 成功取数但为空与所有获取失败产生不同说明，均不生成无依据行业判断。 |
| T11 | 证据与正文版本时间 | 截止后证据被拒绝，原始新闻时间保持不变，现有晚期修订正文防护不因分析日切换而失效。 |
| T12 | 固定输入与缓存 | 改变来源、时间窗口或日期规则需要新输入版本；分析期间新增原始数据不改变已固定输入，旧运行未被覆盖。 |
| T13 | 单日与周期结果归属 | 同一分析交易日不会因跨自然日新闻被重复计为多个入场；单日评估、周期评估和批量历史回放日期一致。 |
| T14 | 三阶段语义分工 | 格式与来源过滤后的输入进入现有 Agent；测试确认程序没有按普通业务关键词整稿淘汰，模型质量另用样本复核。 |
| T15 | 环境变量注入与本地配置兜底 | 仅注入 `TUSHARE_TOKEN` 且本地文件不存在时可以取数；仅有本地文件时也可取数；两者均有值时环境变量优先；空环境变量回退到文件；两者均缺失时明确报错，日志和结果不包含密钥值。 |

### 现有测试先例

- `test_cli_workflow`、`test_run_day_service` 和 `test_stage_pipeline` 已提供公开命令、真实持久化、受控 Worker、封存和评估的工作流先例，作为主要集成测试基础。
- `test_token_batches` 已覆盖同原始日标题规范化合并、空标题分离、准备缓存和分段完整性，可扩展来源过滤与跨日准备场景。
- `test_temporal_integrity` 已覆盖证据发布时间、版本可用时间及修订正文，可扩展盘前截止和分析交易日分离场景。
- `test_baseline_flow`、`test_period` 和 `test_replay` 提供入场评估、周期统计及固定计划先例，应更新旧自然日假设，而不是保留互相冲突的两套预期。

### 实际接口冒烟验证

实现后在已有合法凭据和权限的环境中，对五类接口及报告文档执行小范围冒烟，确认字段、来源参数、条数行为和实际传输可用。记录验证范围及权限缺口，不把有限调用当作完整覆盖或延迟保证。常规回归保持离线可重复，不因真实网络或模型波动而失败。

采集功能及上述工作流测试尚未实现。2026-10-16 已使用本地配置中的 Token 完成基础接口和五类资讯接口的小范围权限验证，详见[接口冒烟验证记录](../research/tushare-api-smoke-20261016.md)；该验证不等于采集与分析功能验收，也不表示应用已实现本地配置读取或环境变量注入。

## Out of Scope

- 持续新闻流、盘中反复分析、后台轮询及本轮固定输入后的追补。
- 新建多时点采集调度平台，或在本次接入飞书机器人并发送消息。
- 扩大用户选定的新闻来源，或通过官网爬虫弥补全部来源覆盖。
- 改为正文相似度去重、按类别或来源分别去重、最长正文优先等新合并规则。
- 新建关键词分类器替代初筛、精筛对宣传稿、行情复述和行业影响的判断。
- 修改 AgentLoom 执行引擎、阶段队列架构或引入分布式采集系统。
- 调整行业判断策略、ETF 候选池、持有期、阈值或计分公式。
- 覆盖、重算或迁移既有已完成运行；旧数据按新口径分析应产生新运行。
- 改写官方 Tushare skill、录入真实密钥或交付云端部署。
- 保证恢复数据商过去每个时刻的原始版本，或宣称事后下载等价于当时实际可获取的数据。

## Further Notes

- 本规格基于本次讨论、项目领域术语和已完成的只读调查；采用“分析交易日”“新闻分析窗口”“新闻截止时刻”“新闻采集缺口”等术语，区分业务完成与采集完整性。
- 日期型整日纳入是已选业务取舍，可能包含起始交易日 15:00 前的内容，不能将这部分标成已精确证明处于秒级窗口。
- Tushare 不提供逐源延迟与全量完整性保证。历史数据可能有延迟录入、后修订正文或重新导出的报告；保存时间与版本依据并保留现有校验，不制造不存在的历史可用时间。
- 开源日历已用 `exchange_calendars` 4.13.2 本地验证，许可证为 Apache-2.0；该版本 `XSHG` 的声明日期上界为 2026-12-31，不能据此推算 2027 年节假日。后续实现需检查实际库版本的覆盖边界，并在需要时更新依赖。参考[开源项目](https://github.com/gerrymanoim/exchange_calendars)及[PyPI](https://pypi.org/project/exchange-calendars/)。
- 2026-10-16 本机已实测官方 REST 地址 `https://api.waditu.com` 可在正常 TLS 校验下成功返回本次接口数据。该事实只覆盖本机验证，不自动证明 SDK 默认传输或云端网络环境具有相同表现。
- 本规格保存在项目内，供后续实现与验收使用；本次没有发布外部 Issue，也不表示业务代码已经实现。
- 本地凭据位置约定为新闻应用配置目录下的 `tushare.local.yaml`，字段为 `token`；参见[无密钥配置模板](../../applications/news_agent/config/tushare.example.yaml)。空本地配置、Git 忽略及打包排除可以先准备，实际配置读取在采集功能实现时接入。
- [前期讨论与只读调查汇总](news-agent-tushare-ingestion.md)保留为背景记录；本规格作为后续实现的统一口径。
