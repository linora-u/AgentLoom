# Tushare 新闻下载、增量补齐与盘前分析

日期：2026-10-16

下载与分析独立运行。自然日数据持久保存，准备阶段选择分析窗口，现有初筛、精筛、校验及冲突校验自动接收新闻正文。复用新闻应用的 CLI、执行引擎和来源配置。

## 来源

| 类别 | 允许来源 |
| --- | --- |
| 新闻快讯 | 财联社、华尔街见闻、第一财经、同花顺 |
| 长篇新闻 | 财联社、华尔街见闻、中证网、新华网、同花顺 |
| 新闻联播文字稿 | all |
| 国家政策库 | all |
| 央行货币政策报告 | all |

all 表示不额外限制该接口提供的来源或机构。请求、保存和分析准备共用来源策略。

## 下载

`download-news` 支持互斥的 `--day DATE`、`--start-date DATE --end-date DATE`、`--incremental`，以及带时区的 `--until DATETIME`。CLI 开始时固定实际截止时间。历史日期范围包含首尾自然日和中间休市日，不依赖交易日历；当天截止不能晚于当前时间。一次命令是一轮有限处理，不持续轮询。

下载保存指定自然日范围内符合来源要求的全部新闻，包括收盘前内容。原始数据按真实发布日期分区，保留发布时间及精度、采集时间、来源、正文和稳定身份；重复请求产生的同一原始记录技术去重，正文变化保留为独立原始记录。央行报告下载 PDF 并提取正文，保留文件哈希、页数、来源地址和采集时间。

达到条数上限时继续分窗；最小范围仍饱和或耗尽有限请求预算，明确记录缺口。新闻接口与 PDF 请求保留代理及 TLS 校验。

## 增量进度

增量范围从截止日期的前一交易日零点到本次截止。截止日期休市时，从最近交易日开始。开源交易日历负责定位交易日，必须检查覆盖范围。

每个接口、请求来源分别汇总已经成功保存的覆盖区间，只补缺口和今天新增时间段。周一包含周五未完成部分、尚未下载的周末及周一新增数据，不设置两个自然日的硬上限。更早缺口由指定日或范围下载补齐。

成功空响应推进进度；请求、解析、文档或保存失败的受影响范围不推进。成功数据落盘后才保存回执和覆盖进度，异常恢复可以重复获取但不能跳过未保存数据。采集器互斥写入，避免覆盖并发写入的原始记录。尚未结束的自然日不能宣称全天完成，日期型接口当天每轮重新检查。

已检查区间可能存在供应商晚到记录；初版不进行无界回看，可通过指定日下载重新检查。

## 重试与错误

可恢复网络错误、超时、HTTP 429 和临时服务错误首次失败后每隔三秒重试，最多额外重试五次，合计六次请求。有效 Retry-After 要求更长等待时遵守它。成功立即结束，最后失败后不再等待。确定性的凭据、权限及参数错误直接报告。

报告完整的异常类型、消息、调用栈、HTTP 状态、业务代码、响应、接口、来源、参数、时间段和重试历史。真实 Token、Authorization 等凭据脱敏。成功空数据与失败分开记录。

单个来源或文档失败不终止其他来源。成功数据保留，独立下载命令有缺口时退出码为 1，错误代码为 news_download_incomplete，结构化 details 包含成功数据及缺口。调用 Agent 据此修正配置、补拉或通知用户；不在本次实现飞书消息发送。

## 输入准备

`prepare --trade-date DATE` 选择前一交易日 15:00 到目标交易日 09:30；`prepare --as-of DATETIME` 选择前一交易日 15:00 到传入的盘前时间点。统一北京时间，包含起点、不包含截止。分析日期必须是受支持的交易日，显式时间必须带时区，且不能晚于该日开盘。

仅日期记录纳入前一交易日及中间休市日全天，排除分析交易日当天，不补造时间戳。不同原始日期可进入同一分析批次。

准备从已下载数据读取，不隐式取数。汇总多份下载回执对窗口的覆盖，来源与分析窗口无需与某一份下载回执完全相同。未覆盖区间、失败原因及文档缺口进入 collection.gaps，采集完整与分析完成分别报告。

先过滤来源和时间，再按原始日期、规范化标题合并；跨媒体、跨类别也合并，保留稳定顺序中第一条正文及所有来源 ID。不比较正文，不跨日期合并，无标题的不同记录分别保留。宣传稿、行情复述及无行业影响内容由既有 Agent 做语义判断，程序不按普通关键词整稿淘汰。

准备完成即固定正文、分段、批次、来源、窗口及哈希。同目录相同设置只返回固定输入，新增下载不改变它。更换窗口、来源、预算或分批目标使用新运行目录。已有不可用采集格式不迁移，不添加兼容分支或版本提示。

## Agent 分析

`run-day --day DATE` 使用准备目录，程序组装正文并依次推进初筛、精筛、校验，必要时执行冲突校验；任务状态与业务结果持久保存，恢复使用原输入及回执。`run-preopen` 是显式下载、准备、分析的组合入口，复用相同实现。

采集部分失败仍分析成功输入，最终结果披露缺口及本次下载诊断；没有可用新闻时返回 no_input，不启动模型。结果归属分析交易日，策略评估从该日开盘入场，run-day 不自动计分。

所有校验证据受本轮截止时间约束。保存发布时间、取得时间和正文哈希；事后取得历史材料不等于已经证明当时可获取，不把下载时间改成历史可见时间。

## 保留与清理

中间新闻、批次、输入清单、业务数据库、阶段结果及日志默认保留。原子写入临时文件及结果暂存目录正常收尾时清理。进程停止与文件清理分开。

run-day 在业务封存、执行成功及本次收尾完成后写入完成回执。cleanup-runs --keep-days N 默认预览，--apply 实际删除配置的 evaluation_output_root/runs/ 下超期完整运行目录。保留期限由完成时间计算。

仅清理全部日期封存、任务完成、具有完成回执且没有活跃调用或执行资源的运行。使用共享运行目录锁与独占清理锁，验证执行资源退出，保留失败、未完成、未识别及资源退出未确认的运行。原始新闻库、下载进度、行情和应用级轨迹不随运行清理。

## 凭据

非空环境变量 TUSHARE_TOKEN 优先；未设置时读取 config/tushare.local.yaml 的 token。没有本地文件时环境变量必须独立可用。配置不提交，不打包，不写入回执或错误。

## 验收

- 指定自然日包含早间新闻，准备仍只选择盘前窗口；日期范围包含周末。
- 前一交易日失败来源补齐，已成功范围不重复下载，今天按固定截止推进。
- 空响应推进进度，失败不推进；数量饱和继续分窗，最小饱和明确报缺口。
- 六次请求上限、三秒等待、Retry-After、PDF 请求和完整脱敏诊断可观察。
- 独立下载部分失败非零退出，成功数据落盘；组合入口继续准备和多 Agent 分析。
- 多次下载覆盖同一窗口，修复缺口后完整性恢复；旧回执路径静默忽略。
- 来源、时间精度及同日同标题规则一致；追加下载不改变固定输入。
- 文档哈希与冻结正文一致，损坏文档隔离；截止后证据不能进入判断。
- 清理预览无删除，实际清理仅处理超期完成运行，活跃、失败、未完成及原始库保留。
- 真实凭据完成小范围取数验证；常规回归使用可控 HTTP、真实文件和既有受控 Worker。
