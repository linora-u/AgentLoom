# Application Harness acceptance

Implementation of public Issue #136 and `application-harnessing-v1.md`. Verification date: 2026-10-21.

## Result

Application YAML can enable a complete-task improvement loop for Supervisor and program-driven applications. Real Agents and subagents execute the base, general/domain probes and composed finals. Only accepted, actually executed finals can be selected and published. Adoption affects the current delivery; subsequent tasks retain their declared base configuration.

The integration follows Harness²'s parallel/sequential exploration, finite positive `k`, composed-final selection and reflection/library behavior. AgentLoom adds ordinary YAML role configuration, development-score feedback, dependency snapshots, application acceptance, physical isolation, usage reconciliation and managed recovery. It does not add automatic default-version promotion, a total-fee wallet or a baseline-artifact fallback.

## Follow-up response privacy

CodeQL identified a real reachable defect: a provider or MCP server could echo its own bound authentication value in otherwise valid generated content. Anonymous credential transport did not prevent that returned value from entering traces or candidates. The fix rejects known in-memory bound credentials in provider responses/errors, tool results and MCP discovery before their first runtime, SDK session or candidate write. Standard JSON-encoded content and arbitrary generated keys are checked; rejected executed tools retain uncertain-effect receipts and failed model invocations retain safe measured usage with incomplete flags. No new policy option was introduced, and ordinary execution without a Harness private scope remains unchanged.

This follow-up uses local controlled HTTP/MCP and the matching rebuilt Pi SDK, not another paid pilot. The final seven Pi provider/MCP/native-output cases passed in 124.46s. A preceding fourteen-case run had thirteen passes and one test-marker failure caused by temporary HOME cleanup; the corrected seven-case Pi subset includes that native-output case. The earlier smol provider/MCP and discovery cases were already green; these results are not represented as a new fourteen-case full-run pass. Independent fixed-revision Spec probes confirmed safe provider adoption, preserved failed usage, physical exit and zero bound values in decompressed trace payloads; private MCP discovery failed before any model request. Exact-head remote CI and CodeQL remain required.

Independent Standards and Spec follow-up reviews of this fixed revision completed with no new findings. These local reviews do not substitute for the updated head's remote checks.

## Real application acceptance

The real request below belongs to its earlier frozen revision, before the response-privacy hardening above. Its original evidence is preserved; it was not rerun or resumed under the new source to claim a new paid acceptance.

A real `parallel`, `k=1`, `contrastive` request completed without experiment errors. All four complete business Trials passed acceptance, sealed their business state and confirmed cleanup. General, domain, compose and reflection each completed on the real provider; the single accepted final was adopted directly, as required for `k=1`.

The selected execution published eight business artifacts whose hashes match the publication manifest. All outer operations and actual business Host jobs confirmed physical exit. A completed resume returned the same decision, artifact hashes, publication generation, trace digest and usage observations, with no new HTTP events, model invocations or publication. Invocation-level known token observations and incomplete-usage flags are retained separately in the private application report; the run is not presented as a precise bill.

The request covers one frozen real news record, one declared instrument and one session. It exercises the normal business stages, acceptance and publication. It does not establish full-day corpus coverage, unseen validation or relative forecasting improvement. Historical source-collection provenance remains explicitly unverified; archive dates are not proof of historical visibility. Future price labels remain outside business Agent access.

Earlier failed/stopped experiments retain their own identities, completed business, known usage, missing measurements and physical-exit receipts. Source or configuration changes create new experiments. Private acceptance receipts retain exact source hashes and invocation-level measurements; no credentials are placed in candidate or experiment archives.

## Operational limits

Harness isolation currently requires Linux with the validated Landlock ABI 6+ and libseccomp capabilities. Unsupported hosts reject enabled execution before model calls. Remote MCP capabilities remain an application/server responsibility. Completed adoption is an executed deliverable, not proof of superiority. Unknown usage stays unknown, and reflection may produce no library entry.
